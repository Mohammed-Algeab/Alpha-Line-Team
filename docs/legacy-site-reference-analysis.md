# تحليل مرجعي للموقع السابق

## نطاق المراجعة

هذا المستند يوثق ما استُخرج من أرشيف `Web-alpha-team-master.zip` المرفوع من المستخدم في 21 أغسطس 2026. التحليل للرجوع الهندسي والبصري فقط؛ لا يمثل قرارًا بنقل شيفرة أو إعادة استخدام هوية الموقع السابق.

## البنية التقنية التي كانت موجودة

كان الموقع السابق تطبيق React مبنيًا بـ Vite ويعتمد `BrowserRouter` ومسارات عميل كثيرة، ثم يجلب المحتوى والإعدادات والتنزيلات من Supabase بعد التحميل. ضمّ أيضًا مصادقة إداريين وتحديثات Realtime وميزات كثيرة قابلة للتبديل. لذلك كان الموقع عمليًا SPA تعتمد تجربته الأساسية على JavaScript وخدمة بيانات خارجية.

حاول المشروع معالجة SEO بعد البناء بواسطة `scripts/generate-pages.mjs`: ينسخ قالب `dist/index.html`، يطلب مشروعات ومنشورات Supabase، ثم يحقن عنوانًا ووسومًا وكتلة HTML مبسطة في كل ملف مشروع أو منشور. هذا تحسين على SPA صِرف، لكنه ليس توليدًا ثابتًا أصيلاً: تفشل عملية التوليد بصمت عندما لا تكون متغيرات Supabase موجودة، والمحتوى المولّد محدود، وعند تحميل React يُستبدل محتوى الجذر بالواجهة التفاعلية.

## ما يجب استبعاده من الموقع الحالي

لا يُنقل نموذج Supabase أو التحديثات الفورية أو صفحة الإدارة أو التحقق من الحسابات؛ فهي تناقض قرار الإدارة الفردية عبر JSON وتضيف نقاط فشل لا يحتاجها الموقع. كما لا تُنقل واجهة البطاقات والحركات من الموقع السابق لأنها تنتمي إلى هوية بصرية مختلفة. ولا يُعاد الاعتماد على `react-helmet` لتكوين الوسوم بعد تحميل الصفحة؛ Astro الحالي ينتج الوسوم والـHTML وقت البناء أصلًا.

## المقارنة مع Alpha Line الحالي

| المجال | الموقع السابق | Alpha Line الحالي | الحكم |
|---|---|---|---|
| الصفحات القابلة للفهرسة | SPA ثم توليد لاحق محدود المحتوى | صفحات Astro مستقلة تُبنى لكل مشروع ومدونة وتصنيف | البنية الحالية أقوى ويجب الحفاظ عليها. |
| البيانات | Supabase واشتراكات فورية | JSON محلي يُستهلك وقت البناء | JSON أنسب لمدير واحد ولموقع قليل التغيير. |
| البحث | بحث محلي بعد جلب البيانات وتحديث URL | بحث محلي ضمن `search.astro` على قائمة مبنية وقت الإنتاج | الفكرة مطبقة بالفعل؛ التحسين اللاحق هو دعم المرادفات وتثبيت الاستعلام في الرابط. |
| سجل الإصدارات | مختصر في الصفحة وأرشيف مستقل | أرشيف إصدارات مستقل موجود | الاقتباس مناسب فقط إذا أضفنا بطاقة مختصرة لآخر ثلاثة إصدارات في صفحة المشروع. |
| تنزيلات متعددة المصادر | صف ديناميكي واحد لكل تنزيل | بيانات المشاريع قابلة للتوسعة في JSON | هذه أفضل فكرة عملية للمرحلة التالية مع روابط تنزيل حقيقية. |

## قرار مرحلي مقترح

لا يلزم نقل أي ميزة الآن قبل أن يكتمل التعريب الأول. عند الاقتراب من أول إصدار، يُنفَّذ أولًا نموذج تنزيل منظم في JSON، ثم ملخص آخر ثلاثة إصدارات في صفحة المشروع، ثم صفحة إخلاء استخدام مرتبطة بالتنزيلات. بعد زيادة عدد المشاريع والمقالات فقط، يمكن تطوير البحث المحلي إلى فهرس يدعم أسماء الألعاب العربية والإنجليزية والاختصارات، من دون خادم أو قاعدة بيانات.
