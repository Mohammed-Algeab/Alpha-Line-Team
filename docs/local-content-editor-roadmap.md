# خارطة طريق أداة تحرير محتوى Alpha Line المحلية

## القرار المعتمد

لن ينشئ الموقع **صفحة إدارة عامة** أو قاعدة بيانات أو واجهة API في الإصدار الأول. يبقى الموقع مبنيًا مسبقًا من ملفات JSON ويُرفع إلى GitHub ثم Cloudflare Pages، وهو ما يحافظ على سرعة الصفحات ووضوح بنية المحتوى وقابلية الفهرسة.

ستكون أداة الإدارة المستقبلية برنامج سطح مكتب محليًا منفصلًا، يُشغَّل على جهاز محرر موثوق داخل نسخة المستودع. وظيفتها هي تعديل ملفات المحتوى والتحقق منها ثم فتح المعاينة المحلية؛ وليست نسخة أخرى من الموقع ولا خادمًا عامًا.

> **المحاكاة الصحيحة للموقع هي المعاينة المحلية نفسها عبر `pnpm dev`.** لا حاجة إلى إعادة بناء واجهة الموقع داخل البرنامج؛ تحتاج الأداة فقط إلى جعل إدخال البيانات وتعديلها أكثر أمانًا وسهولة.

## نطاق الإصدار الأول من الأداة

| المجال | ما ستفعله الأداة | ما لن تفعله |
|---|---|---|
| المشاريع | إنشاء مشروع V2، تعديل الاسم والحالة والمراحل والسلسلة والمنصة والوصف والغلاف | إنشاء صفحات HTML يدوية أو تغيير قوالب Astro |
| الأصول | حفظ رابط الغلاف أو مساره العام في JSON والتحقق من صيغته | رفع صور إلى R2 أو أي خدمة خارجية تلقائيًا |
| الإصدارات | إضافة إصدار حقيقي وتنزيلاته وتعليماته فقط بعد تفعيل النشر | اختراع أرقام إصدارات أو روابط تنزيل تجريبية |
| الجودة | تشغيل `pnpm validate:content` ثم `pnpm build` وعرض الأخطاء بوضوح | تجاهل فشل التحقق أو النشر تلقائيًا إلى الإنترنت |
| المعاينة | بدء `pnpm dev` وفتح رابط المعاينة المحلي في المتصفح | محاكاة تصميم الموقع داخل نافذة منفصلة |
| GitHub | عرض الملفات المعدلة أو فتح المستودع للمستخدم | حفظ مفاتيح أو كلمات مرور أو تنفيذ رفع قسري بلا مراجعة |

## البنية التقنية المقترحة

سيُبنى البرنامج بـ**Python وPySide6**. تكفي في البداية المكتبات القياسية (`json` و`pathlib` و`subprocess` و`shutil`) مع PySide6 للواجهة. سيعتمد مصدر الحقيقة الحالي نفسه: `src/content/projects/*.json` و`src/content/blog/*.json` و`src/content/site.json`.

بدل إعادة تنفيذ قواعد المحتوى مرتين في Python، تشغّل الأداة أمر المشروع الحالي `pnpm validate:content`. لذلك تبقى قواعد Zod الموجودة في `scripts/validate-content.mjs` المرجع الوحيد لصحة محتوى V2، ويظهر الخطأ للمحرر قبل أن يرفع أي تغيير إلى GitHub.

## تجربة الاستخدام المقصودة

1. يختار المستخدم مجلد نسخة Alpha Line المحلية عند أول تشغيل.
2. تتحقق الأداة من وجود `package.json` ومجلدات المحتوى ثم تعرض قائمة المشاريع والمقالات.
3. يفتح المحرر مشروعًا عبر نموذج عربي واضح، أو ينشئ مشروع V2 جديدًا من قالب صادق بلا إصدار أو تنزيلات.
4. يضع رابط غلاف المشروع داخل حقله في JSON. يمكن أن يكون رابط `https://` أو مسارًا عامًا يبدأ بـ`/` عندما تُحفظ صورة صغيرة ضمن الموقع.
5. عند الحفظ، تكتب الأداة JSON منسقًا ذريًا وتحتفظ بنسخة احتياطية محلية قصيرة قبل الاستبدال.
6. ينفذ المستخدم زر **التحقق والبناء**. لن تقترح الأداة رفع التغييرات إذا فشل التحقق أو البناء.
7. عند الحاجة، يضغط زر **فتح المعاينة** فتبدأ `pnpm dev` ويُفتح الموقع الحقيقي في المتصفح؛ بعد المراجعة يستخدم Git بنفسه لعمل commit وpush.

## شاشات الأداة المستقبلية

| الشاشة | الغرض |
|---|---|
| لوحة البداية | اختيار المجلد، حالة `pnpm`، وآخر نتيجة للتحقق والبناء |
| المشاريع | قائمة المشاريع وحالتها، مع إنشاء مشروع V2 جديد من قالب |
| محرر المشروع | بيانات اللعبة، الغلاف، المراحل، التوافق، النطاق، الإصدار والتنزيلات |
| المقالات | إنشاء أو تعديل مقالة JSON ومسودتها وحالة النشر |
| الفحص | مخرجات `validate:content` و`build` بنص قابل للنسخ |
| المعاينة | تشغيل أو إيقاف المعاينة المحلية وفتحها في المتصفح |
| التغييرات | قائمة الملفات المعدلة مع خيار فتح المجلد أو تشغيل `git diff` فقط |

## شروط التنفيذ قبل البدء

لا يبدأ بناء الأداة الآن. يبدأ عندما تستقر الحقول الفعلية لأول مشروع قابل للتنزيل، خصوصًا نموذج `release` و`downloads` وتعليمات التثبيت. عندئذ لن تصمم واجهة بناءً على حقول افتراضية ستتغير لاحقًا.

يُمنع في الإصدار الأول من الأداة أي اتصال بقاعدة بيانات أو خدمة سحابية أو أي حفظ لبيانات دخول. يظل GitHub وCloudflare Pages مسار النشر، وتظل الأداة طبقة تحرير محلية قابلة للاستبدال وليست شرطًا لتشغيل الموقع.

## معايير القبول عند تنفيذ الأداة

- تستطيع إنشاء مشروع V2 صحيح مع غلاف موجود داخل JSON نفسه.
- تمنع إضافة تنزيل أو إصدار إذا كان `release.published` غير مفعّل.
- تعرض أخطاء Zod والبناء بأسم الملف والرسالة.
- تفتح المعاينة الحقيقية للموقع بدل تقليدها.
- لا تضيف خادمًا عامًا ولا تؤثر في HTML الثابت أو SEO.
- لا تضع أسرارًا أو ملفات ألعاب أو باتشات داخل المستودع العام.
