# متطلبات Alpha Line المعتمدة

> **المصدر:** استبيان تطوير Alpha Line، الأسئلة 1–120. هذه الوثيقة مرجع قرار داخلي، وليست نصًا تسويقيًا أو وعدًا عامًا للزوار.

## 1. الغاية وترتيب الأولويات

Alpha Line هو **فريق عربي لتعريب الألعاب** يبدأ بـSteins;Gate وسلسلة Science Adventure، ويمكنه التوسع إلى ألعاب وسلاسل أخرى عندما تتوفر القدرة الفعلية. لا يَعِد الموقع بموعد غير مؤكد أو بإكمال سلسلة كاملة لمجرد إعلان الاهتمام بها.

> **مبدأ غير قابل للتغيير:** التعريبات أولًا، ثم SEO والبنية التقنية، ثم التصميم.

| الأولوية | المعيار المعتمد |
|---|---|
| 1 | صفحة مشروع دقيقة ومفيدة للاعب، مع ملف تنزيل وتوافق وتعليمات واضحة. |
| 2 | صفحات HTML ثابتة قابلة للفهرسة، وروابط قصيرة، وسرعة تحميل جيدة على الهاتف. |
| 3 | هوية هادئة ورسمية تعزز الثقة، من دون أن تسبق وضوح المعلومة أو جودة التعريب. |

## 2. البنية التقنية والنشر

يبقى المشروع **Astro Static Site** يولّد HTML مستقلًا لكل صفحة مشروع وسلسلة ومقال وتصنيف. تبقى البيانات في ملفات JSON وMarkdown قابلة للمراجعة في GitHub، ولا توجد قاعدة بيانات أو لوحة إدارة أو SPA في النطاق الأولي.

يتبع التعديل مسارًا بسيطًا: تحرير المحتوى، معاينته محليًا بواسطة `pnpm dev`، تشغيل فحوص البناء، ثم دمج التعديل في GitHub. ينشر Cloudflare Pages النسخة الثابتة تلقائيًا من فرع الإنتاج. لا يضع المستودع المفتوح روابط خاصة أو بريدًا شخصيًا أو أسماء حقيقية غير مصرح بها.

| القرار | النطاق الأول | التوسع اللاحق |
|---|---|---|
| محررو المحتوى | المالك فقط. | محررون موثوقون بقوالب JSON ومراجعة قبل الدمج. |
| تخزين الصور | Cloudflare R2 أو تخزين صور خارجي مناسب. | تنظيم صلاحيات رفع الأصول عند توسع الفريق. |
| ملفات التعريب | مصادر خارجية عامة مثل MediaFire وTelegram وGitHub. | رابط مباشر من بنية تخزين الفريق عند توافرها. |
| النسخ الاحتياطي | تاريخ GitHub للمحتوى والكود. | نسخة خارجية للأصول عند نموها. |

## 3. نموذج المحتوى

المشروع هو الوحدة الأساسية للموقع. له حالة عامة ومراحل عمل شفافة وإصدارات مستقلة وروابط تنزيل، ويمكن ربطه بسلسلة مستقلة. لا تستخدم الواجهة نسبة مئوية افتراضية؛ بل تعرض المرحلة الحالية وموقعها من تسلسل مراحل خاص بالمشروع.

| الكيان | البيانات الإلزامية | البيانات الاختيارية |
|---|---|---|
| مشروع | الاسم العربي والأصلي، الرابط، الحالة، نوع المشروع، المنصة، السلسلة، السنة، المراحل. | قصة/سبب التعريب، صورة غلاف، مساهمون، تحذير محتوى. |
| إصدار | رقم الإصدار، التوافق، تاريخ الإصدار، نطاق التعريب، سجل موجز، مصادر التنزيل. | تعليمات مصورة أو فيديو، مشكلات معروفة، شارة «إصلاح». |
| سلسلة | الاسم العربي والأصلي والرابط ووصف موجز. | غلاف أو ملاحظات تحريرية. |
| مقال | العنوان والرابط والتاريخ والكاتب. | تصنيف، غلاف، وروابط مشاريع ذات صلة. |

### حالات المشروع

الحالات المعتمدة هي: **مخطط، جاري تنفيذ، مكتمل، مؤجل، متوقف، ملغي**. تظهر المشاريع المخططة في صفحة الخطط فقط عند وجود قرار عمل واقعي. تفهرس محركات البحث المشاريع الجارية والمكتملة؛ أما المؤجلة والمتوقفة والملغاة فلا تحتاج الظهور في نتائج البحث العامة.

### الإصدارات والتنزيل

يحتوي كل إصدار على ما يحتاجه اللاعب قبل الضغط: إصدار اللعبة المتوافق، المنصة، تاريخ الإصدار، نوع الملف وحجمه عند توفرهما، ونطاق ما عُرِّب وما بقي خارج النطاق. يفتح زر «تنزيل» نافذة داخل الموقع لا تعرض إلا المصادر المتاحة لذلك الإصدار. يمكن إبراز ثلاثة تنزيلات يحددها محرر المشروع يدويًا، مع ترتيب مفضل افتراضي هو MediaFire ثم GitHub ثم Telegram ثم الرابط المباشر المستقبلي.

تبقى الإصدارات القديمة قابلة للتنزيل ما لم يسبب أحدها ضررًا للعبة. عند وجود مشكلة متحققة، تظهر بوضوح قبل التنزيل وداخل سجل الإصدار المتأثر، ويُسحب الملف الضار بدل ترك رابط مكسور أو غير آمن.

## 4. بنية الموقع وتجربة الزائر

القائمة الأساسية المعتمدة هي: **الرئيسية، التعريبات، المدونة، حول الفريق، الدعم أو التواصل**. يظل الدعم صفحة مؤجلة ولا يظهر كرابط عام قبل تحديد آليته. تضاف صفحة خطط مستقلة، لكنها تُولد من بيانات المشاريع نفسها، إضافة إلى صفحة للتعريبات المستقلة وصفحات السلاسل.

| الصفحة | الوظيفة المعتمدة |
|---|---|
| الرئيسية | المشروع المميز، مشاريع، مدونات، أخبار، خطط، تعريف موجز بالفريق، وتواصل. |
| أرشيف التعريبات | البحث والفلاتر الأساسية: الحالة والمنصة والسلسلة؛ ويتعامل بهدوء مع غياب مشاريع مكتملة. |
| صفحة المشروع | غلاف اللعبة، الاسم، الحالة والمرحلة في الرأس، ثم تعريف قصير وموسع، الإصدارات والتنزيل والتوافق والتثبيت والمساهمون والمواد المرتبطة. |
| صفحة السلسلة | تجمع كل مشاريع السلسلة بغض النظر عن نوع المشروع. |
| التعريبات المستقلة | أرشيف مستقل ببنية قريبة من أرشيف التعريبات العام. |
| المدونة | بطاقات بتاريخ وبحث وتصنيفات اختيارية، مع ربط المشروع أو اللعبة عند وجود صلة تحريرية. |
| حول الفريق | تعريف موجز بالفريق ككيان واحد، مع أعضاء اختيارين بالاسم فقط. |
| 404 | صفحة ذات مظهر خاص تقود بوضوح إلى الرئيسية. |

## 5. البحث وSEO

تعتمد عناوين وروابط الصفحات على صيغ إنجليزية قصيرة وثابتة، مثل `/translations/steins-gate/`، بينما يبقى المحتوى العربي هو اللغة الرئيسية للقراءة. تدعم بيانات البحث الاسم العربي والاسم الأصلي والاختصارات واسم السلسلة، مثل «شتاينز غيت» و`Steins;Gate` و`SciADV`.

يقتصر الظهور في محركات البحث على الرئيسية والمقالات المنشورة والمشاريع الجارية أو المكتملة. لا تظهر المسودات أو صفحات الاختبار أو الانضمام أو الصفحات الداخلية غير التحريرية. تعطي بطاقة مشاركة المشروع الأولوية لغلاف اللعبة مع علامة Alpha Line، ولا يتوسع نظام البطاقات في البداية إلى كل أنواع المحتوى.

## 6. الثقة والمحتوى والمجتمع

يتبنى الموقع دقة تقنية واقعية، ومراجعة بشرية دقيقة للنصوص، واستجابة مسؤولة لتقارير الأخطاء. لا يقدم مخرجات غير مدققة على أنها تعريب جاهز. تظهر أسماء أعضاء الفريق والمساهمين بحسب رغبتهم، مع تمييز واضح بين الفئتين.

يوضح الموقع أن Alpha Line يوفر ملفات تعريب لا الألعاب الأصلية، ويربط بمصدر رسمي للعبة عندما يكون ذلك ممكنًا. يحتاج الموقع إلى سياسة استخدام مبسطة لملفات التعريب يمكن وضع ملخص منها في المثبّت، كما يحتاج إلى تحذير واضح للألعاب ذات المحتوى الناضج غير الصريح. الألعاب الإباحية الصريحة خارج نطاق الفريق.

تُستخدم المدونة للأخبار والشروح التقنية والمقالات عن الألعاب وإعلانات التعريبات عند وجود مادة تستحق النشر، من دون جدول مصطنع. وتُجهز Telegram أولًا قبل الإعلان، مع قوالب TikTok للصور أو الفيديوهات، بينما لا تظهر روابط قناة عامة قبل تجهيزها.

## 7. الإطلاق الأول ومؤشرات النجاح

لا يعلن الموقع علنًا قبل شراء نطاق مخصص ووجود أول إصدار قابل للتحميل من Steins;Gate يتضمن الفصلين 0 و1. الحد الأدنى للإطلاق هو الرئيسية وأرشيف التعريبات وصفحة المشروع، مع أن صفحة المشروع هي أولوية التدقيق البصري والوظيفي.

| شرط القبول | ما يعنيه عمليًا |
|---|---|
| معلومات دقيقة | توافق الإصدار ونطاق التعريب وروابط التنزيل وتعليمات أساسية تم التحقق منها. |
| سرعة جيدة | لا صور محلية ضخمة ولا جافاسكربت غير ضروري، وتجربة هاتف خفيفة. |
| SEO جاهز | رابط مخصص، sitemap وrobots وcanonical وبطاقات مشاركة صحيحة وصفحات قابلة للفهرسة. |
| إعلان قابل للمتابعة | قناة Telegram جاهزة ورابط المشروع يفتح ويعمل من الهاتف. |

يقاس النجاح الأولي بوجود تنزيلات فعلية وظهور صفحات الموقع في Google، لا بحجم الإحصاءات أو عدد المزايا.

## 8. عناصر مؤجلة وقرارات مفتوحة

| العنصر | سبب التأجيل أو القرار المطلوب لاحقًا |
|---|---|
| المثبّت الخاص بـAlpha Line | منتج منفصل؛ يعرضه الموقع عند جاهزيته ولا يعتمد تصميم الموقع عليه مسبقًا. |
| شكل تعليمات التثبيت النهائية | يحدد بعد أول إصدار حقيقي: نص فقط أو صور أو فيديو. |
| مكان سجل الإصدارات الكامل | صفحة مستقلة أو قسم موسع في صفحة المشروع، ويقرر من استخدام النسخة الأولى. |
| البريد الرسمي | يربط مزود بريد بالنطاق قبل إظهاره؛ لا يكفي شراء النطاق وحده. |
| قسم الدعم وجمع التبرعات | يتطلب سياسة واضحة للتكاليف وتوزيع الدعم وموافقة الفريق. |
| الإحصاءات | لا تضاف حتى يظهر سؤال تشغيلي يبرر جمعها. |
| سياسة الخصوصية | تنشر عند إضافة تحليلات أو نموذج أو خدمة تجمع بيانات. |
| صفحة حول الفريق والتذييل | تنتظر المواد والروابط والقنوات الحقيقية بدل ملئها بنصوص شكلية. |
