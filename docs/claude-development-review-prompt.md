# Prompt لمراجعة Alpha Line في Claude

انسخ النص التالي إلى Claude بعد رفع ملف `alpha-line-site-source.zip` معه.

---

أنت مهندس برمجيات ومصمم تجربة مستخدم متخصص في المواقع الثابتة القابلة للنمو. راجع شفرة مصدر موقع **Alpha Line / ألفا لاين** المرفقة، وهو موقع عربي RTL لفريق تعريب ألعاب يبدأ بسلسلة SciADV، ثم اكتب **خطة تطوير عملية ومنضبطة**. لا تكتب كودًا الآن، ولا تقترح إعادة بناء المشروع من الصفر ما لم تجد سببًا تقنيًا قاطعًا.

## هدف الموقع

الموقع أرشيف رسمي وهادئ لتعريبات الألعاب. يجب أن يظل Static Site حقيقيًا، محسّنًا لـ SEO، سهل الإدارة يدويًا من ملفات JSON/Markdown، ومن دون قاعدة بيانات أو لوحة تحكم أو backend في المرحلة الحالية.

## التقنيات والقيود الثابتة

| المجال | القرار الحالي |
|---|---|
| الإطار | Astro بوضع `output: "static"` |
| اللغة والاتجاه | عربية RTL مع تسميات تقنية إنجليزية صغيرة |
| المحتوى | ملفات JSON في `src/content/projects/` و`src/content/blog/` |
| بناء الصفحات | `pnpm build` وينتج مجلد `dist/` |
| الاستضافة المستهدفة | Cloudflare Pages عبر GitHub |
| قاعدة البيانات | غير مطلوبة حاليًا |
| الصور | روابط CDN أو استضافة خارجية، لا وسائط كبيرة داخل المستودع |
| التصميم | أطلس المسارات / Contemporary Editorial Wayfinding: كحلي حِبري، عاجي للنص، سماوي للإشارات، بطاقات دوسيه مفهرسة |

## ما هو موجود بالفعل

المشروع يحتوي على صفحات HTML ثابتة مستقلة للرئيسية، أرشيف التعريبات، صفحة مشروع، سجل الإصدارات، التصنيفات، المدونة، المقالات، حول الفريق، التواصل، البحث، robots.txt وsitemap.xml. يوجد SEO أساسي وOpen Graph افتراضي وبطاقات Open Graph ديناميكية للمشاريع. كما توجد حزمة شعار: علامة مربعة للهاتف والحسابات، وقفل علامة مركب في رأس سطح المكتب.

## ما أريده منك

1. **حلل البنية الحالية**: قيّم نموذج المحتوى، المسارات، توليد الصفحات، بيانات SEO، قابلية الصيانة، توافق Cloudflare Pages، وتجربة الهاتف.
2. **اذكر ما هو جيد ولا يجب تغييره** قبل اقتراح أي تحسين.
3. **اكتشف المخاطر أو العيوب الحقيقية فقط**، مع ذكر الملف أو المنطقة ذات الصلة وسبب المشكلة وتأثيرها. لا تخترع مشاكل افتراضية.
4. **رتّب التحسينات في ثلاث مراحل**:
   - قبل الإطلاق العام.
   - بعد أول مشروع/تعريبة منشورة.
   - عند نمو الفريق أو عدد المشاريع.
5. لكل تحسين، وضّح: الأولوية، الفائدة، الجهد التقريبي (صغير/متوسط/كبير)، هل يحتاج تغييرًا في المحتوى أو التصميم أو البنية، وهل يظل الموقع Static.
6. قيّم هل نحتاج فعلًا إلى: بحث محلي، Markdown للمدونة، التحقق من JSON في وقت البناء، صفحات 404، Analytics، CI بسيط، صفحات قانونية، دعم PWA، أو لوحة إدارة. كن صارمًا ضد التعقيد غير المبرر.
7. اقترح **أفضل طريقة للنشر عبر GitHub + Cloudflare Pages**، بما في ذلك الإعدادات التي يجب تغييرها عند شراء الدومين.
8. قدّم في النهاية **Backlog من 10 عناصر كحد أقصى**، مرتبًا حسب الأولوية، يمكن لصاحب المشروع تنفيذه تدريجيًا.

## قواعد الإجابة

- اكتب بالعربية الواضحة، مع إبقاء أسماء الملفات والحقول البرمجية كما هي.
- لا تقترح React SPA أو قاعدة بيانات أو Supabase أو CMS خارجي إلا إذا قدمت مبررًا قويًا جدًا.
- لا تستبدل Astro أو نظام المحتوى الحالي لمجرد التفضيل الشخصي.
- لا تُضف تقييمات أو شهادات مستخدمين وهمية.
- احترم الهوية البصرية: لا تقترح تحويلاً إلى واجهة فاتحة أو ألوان بنفسجية متوهجة أو تصميم SaaS عام.
- افترض أن المدير شخص واحد الآن، وأن أهم أولوية فعلية هي **إنهاء أول تعريبة** لا توسيع الموقع بلا نهاية.
- لا تنفذ أي تعديل. أريد تقريرًا وخطة فقط.

## بنية الإجابة المطلوبة

1. ملخص تنفيذي من فقرتين.
2. ما الذي يعمل جيدًا ويجب الحفاظ عليه.
3. جدول نقاط التحسين والمخاطر.
4. خارطة طريق المراحل الثلاث.
5. إعداد النشر والدومين.
6. Backlog نهائي من 10 عناصر أو أقل.
