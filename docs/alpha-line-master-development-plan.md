# خطة تطوير Alpha Line الموحدة

> **الإصدار:** 1.0  
> **المرجع:** الاستبيان المكتمل، و`accepted-requirements.md`، و`implementation-roadmap.md`، ومواصفات نماذج المحتوى.  
> **مبدأ التنفيذ:** التعريبات أولًا، ثم قابلية العثور عليها وسلامة بنيتها التقنية، ثم التحسين البصري. لا يُضاف شيء لمجرد أنه ممكن تقنيًا.

## 1. الهدف العملي

هدف هذه الخطة هو تحويل Alpha Line من موقع Astro ثابت بهيكل بصري قائم ومحتوى تجريبي إلى **مرجع عربي موثوق لتعريبات الفريق**. عند الإطلاق العام، يجب أن يتمكن اللاعب من العثور على صفحة Steins;Gate في محركات البحث، فهم حالة التعريب ونطاقه وتوافقه، تنزيل الباتش من هاتفه أو حاسوبه، تثبيته بوضوح، ثم الوصول إلى قناة إبلاغ موحدة عند مواجهة مشكلة.

لا يعني ذلك بناء لوحة إدارة أو قاعدة بيانات أو تطبيقًا معقدًا. يبقى الموقع **Static Site** مولدًا لصفحات HTML مستقلة من ملفات JSON، ويُدار التحرير في البداية عبر GitHub مع معاينة محلية. ويُعلن الموقع علنًا فقط عندما يتوفر إصدار حقيقي للفصلين 0 و1 من Steins;Gate، مع نطاق مخصص وروابط تنزيل مدققة.

## 2. نقطة البداية الحالية

| المجال | الحالة الحالية | ما يعنيه ذلك للخطة |
|---|---|---|
| البنية | Astro ثابت يولد صفحات HTML مستقلة، والبناء ناجح. | لا نعيد بناء المشروع بإطار SPA أو قاعدة بيانات. |
| الهوية | الشعار، نسخة الهاتف، والـWordmark للحاسوب، وهوية «أطلس المسارات» موجودة. | نحافظ على اللغة البصرية ولا نغيرها إلا لتحسين القراءة أو الوصول. |
| المحتوى | توجد ملفات JSON ومشاريع تجريبية وصفحات مشاريع. | تُرحّل تدريجيًا إلى النموذج الجديد بدل كسر البنية الحالية دفعة واحدة. |
| SEO | يوجد sitemap وrobots وبطاقات مشاركة، لكن توجد إصلاحات معلقة لصور Open Graph والدومين و404. | هذه عناصر حرجة قبل الإعلان العام. |
| الاستضافة | لم يُربط GitHub وCloudflare Pages بعد. | الربط يأتي بعد اجتياز معاينة محلية وبناء إنتاجي ناجح. |
| الإطلاق | لا توجد بعد روابط تنزيل أو قنوات مجتمع جاهزة أو وصف Steins;Gate النهائي. | المحتوى الحقيقي هو بوابة الإطلاق؛ التصميم وحده لا يكفي. |

## 3. مبادئ لا تتغير

تعمل Alpha Line كفريق تعريب لا كمكتبة تنزيلات عشوائية. لهذا ترتكز القرارات القادمة على الدقة التقنية، والمراجعة البشرية للنص، والوضوح بشأن ما يترجمه كل إصدار وما لا يترجمه. لا يُعرض تقدم وهمي كنسبة مئوية، ولا يُعطى موعد إصدار غير مؤكّد، ولا يُعلن عن سلسلة كاملة لمجرد الرغبة في تعريبها.

| المبدأ | التطبيق المباشر |
|---|---|
| الدقة قبل السرعة | كل إصدار يحدد توافق اللعبة ونطاق التعريب ومشكلاته المعروفة بدل ادعاء الاكتمال. |
| الوضوح قبل الزخرفة | زر التنزيل لا يسبق معلومات التوافق أو التحذير ذي الصلة. |
| SEO قبل التوسع | كل صفحة عامة لها عنوان ووصف ورابط ثابت وفهرسة مقصودة. |
| Static أولًا | المحتوى من JSON، والنشر من GitHub إلى Cloudflare Pages، من دون قاعدة بيانات. |
| الهاتف أولًا | التنزيل، نافذته، تعليمات التثبيت، والقائمة تُفحص على هاتف قبل اعتبارها جاهزة. |
| الشفافية | التأجيل والإلغاء والمشكلات المعروفة تُعالج بلغة صريحة ومختصرة بعد التحقق. |

## 4. نطاق الإطلاق الأول

الإطلاق العام لا يحتاج كل الصفحات أو كل الأفكار. الحد الأدنى المعتمد هو أن تعمل الصفحة الرئيسية، وأرشيف التعريبات، وصفحة Steins;Gate الفردية بكامل مسارها. أما المدونة والخطط والسلاسل وصفحة الفريق فتُبنى بمستوى صحيح تقنيًا، لكن لا تؤخر أول إصدار إذا لم يتوفر لها محتوى حقيقي.

| يدخل في الإطلاق الأول | يؤجل لما بعد الإطلاق |
|---|---|
| الرئيسية، أرشيف التعريبات، وصفحة مشروع كاملة. | صفحة دعم أو جمع تبرعات. |
| حالة المشروع ومراحله ونطاق التعريب. | إحصاءات الزيارات والتتبع التسويقي. |
| إصدار واحد حقيقي أو أكثر، وسجل إصدارات، وروابط تنزيل. | قاعدة بيانات أو لوحة تحكم أو تطبيق إدارة. |
| تعليمات تثبيت، وقناة إبلاغ، وتحذير محتوى عند الحاجة. | لغات أخرى أو واجهة متعددة اللغات كاملة. |
| SEO وOpen Graph و404 والدومين النهائي. | بحث متقدم لا تبرره كمية المحتوى. |
| Telegram جاهز ورابطه صحيح. | Discord احترافي كامل أو حملة TikTok كبيرة. |

## 5. خارطة التنفيذ الرئيسية

### المرحلة A — تثبيت التقنية والـSEO

هذه المرحلة يجب أن تنتهي قبل أي توسع كبير في الواجهة. الغرض منها منع نشر صفحات جميلة تقود إلى صور مشاركة معطلة، أو روابط غير موحدة، أو نتائج بحث ضعيفة.

| المهمة | المخرج المطلوب | معيار القبول |
|---|---|---|
| إصلاح Open Graph الافتراضي | ملف صورة افتراضية حقيقي ومتاح للزحف والمشاركة. | `og:image` لا يعيد 404 في البناء الإنتاجي. |
| ضبط Open Graph للمشروع | كل صفحة مشروع ترتبط ببطاقة مبنية من غلاف اللعبة وعلامة Alpha Line. | بطاقة مشاركة Steins;Gate تعرض الغلاف والشعار بوضوح. |
| إنشاء صفحة 404 | صفحة مستقلة متسقة مع الهوية تقود للرئيسية. | أي مسار غير صحيح يعطي 404 فعليًا مع مسار خروج واضح. |
| توحيد SEO قبل الدومين | قيمة موقع مؤقتة موحدة في canonical وsitemap وrobots. | لا توجد روابط متضاربة في ناتج البناء. |
| ربط الدومين لاحقًا | استبدال القيمة المؤقتة بعد الشراء. | كل الروابط القانونية والسitemap وOpen Graph تستخدم الدومين النهائي. |
| تدقيق السرعة | الأصول الثقيلة خارج المستودع وروابط الصور محسنة. | لا توجد وسائط كبيرة محلية تعيق نشر الموقع. |

**قرار التنفيذ:** لا تُنشأ مزايا جديدة إذا ظل رابط مشاركة أو صفحة 404 أو canonical مكسورًا؛ هذه مشاكل تؤثر في الثقة مباشرة.

### المرحلة B — ترحيل نماذج المحتوى

تعتمد هذه المرحلة المواصفات الموجودة في `project-content-model-v2.md` و`series-content-model-v1.md` و`blog-content-model-v2.md`. لا تُملأ مشاريع وهمية لإثبات أن المخطط يعمل؛ تبدأ الهجرة بمشروع Steins;Gate ثم تعمم عند ثبات التجربة.

#### B.1 مشروع التعريب

كل ملف مشروع يدعم، مع الحفاظ على الحقول القديمة مؤقتًا:

| الحقل أو المجموعة | الغرض |
|---|---|
| `status` | مخطط، جاري تنفيذ، مكتمل، مؤجل، متوقف، أو ملغي. |
| `projectType` | مشروع فريق أو تعريب مستقل، من دون أن يؤثر في انتمائه إلى سلسلة. |
| `series` | ربط المشروع بسجل سلسلة مستقل مثل SciADV. |
| `stages` | مراحل مخصصة للمشروع بدل نسبة تقدم مضللة. |
| `aliases` | الاسم العربي والإنجليزي والاختصارات لتحسين البحث الداخلي والـSEO. |
| `indexing` | قرار صريح بشأن الظهور في Google؛ الجاري والمكتمل فقط افتراضيًا. |
| `overview` | وصف قصير ووصف موسع، مع قصة أو سبب تعريب اختياري. |
| `contributors` | أعضاء الفريق والمساهمون، ويظهرون فقط بموافقتهم وبالاسم المناسب لهم. |

#### B.2 الإصدارات والتنزيل

كل إصدار يحتوي رقمًا وتاريخًا وتوافقًا مع نسخة اللعبة والمنصة ونوع الملف ونطاق التعريب وسجلًا موجزًا ومشكلات معروفة. يحتفظ الموقع بكل الإصدارات القابلة للتنزيل ما لم يكن إصدار معين يضر اللعبة أو يسبب خطأً كبيرًا.

| القرار | التطبيق |
|---|---|
| ثلاثة تنزيلات بارزة | يختار المحرر يدويًا حتى ثلاثة روابط يمكن عرضها مباشرة. |
| نافذة تنزيل واحدة | زر «تنزيل» يفتح المصادر المتاحة فقط: Telegram أو MediaFire أو GitHub أو رابط مباشر مستقبلًا. |
| التحذير قبل التنزيل | المشكلات المعروفة تظهر قرب الإصدار وزر التنزيل، لا في مكان مخفي. |
| شارة واحدة مفيدة | تستخدم شارة «إصلاح» عند الحاجة، دون نظام شارات معقد. |
| الإبلاغ موحد | روابط Telegram وDiscord والبريد تكون قابلة لإعادة الاستخدام في كل مشروع. |

### المرحلة C — إتقان صفحة المشروع

هذه أهم مرحلة في الخطة، وهي الصفحة التي تحدد إن كان اللاعب يثق بالموقع ويحمل الملف أم لا. لا تُعمم مكونات الصفحة الجديدة على بقية المشاريع قبل اجتيازها في Steins;Gate على الهاتف والحاسوب.

| ترتيب الصفحة | المحتوى المطلوب | قرار تجربة المستخدم |
|---|---|---|
| 1. الرأس | غلاف اللعبة، الاسم العربي والأصلي، الحالة، والمرحلة الحالية. | لا يزدحم الرأس بالتنزيل أو التحديثات. |
| 2. التعريف | وصف قصير ثم وصف موسع اختياري. | قسم قصة التعريب أو سبب الاختيار قابل للإخفاء بالكامل. |
| 3. حالة التعريب | مراحل واضحة ونطاق الإصدار الحالي. | يبين ما تمت ترجمته وما لا يزال خارج النطاق. |
| 4. الإصدار والتنزيل | التوافق والتاريخ ونوع الملف وروابط التنزيل. | التنزيل مباشر، مع تحذير واضح عند وجود مشكلة. |
| 5. التثبيت | خطوات نصية قصيرة قابلة للتحديث. | تضاف صور أو فيديو فقط عندما تفيد فعليًا. |
| 6. المساعدة والثقة | الإبلاغ والمساهمون وتحذير المحتوى وسياسة الاستخدام. | لا تظهر بلاغات عامة قبل أن تتحقق منها الإدارة. |

**ملاحظة عن المثبّت:** مثبّت Alpha Line مشروع منفصل عن الموقع. لا يجب أن يؤخر صفحة المشروع؛ يكفي في البداية أن تشرح الصفحة نوع الملف وطريقة تشغيله بدقة، ثم توسع تجربة المثبّت عندما يصبح موجودًا.

### المرحلة D — الأرشيفات والسلاسل والبحث

تنفذ هذه المرحلة بعد ثبات صفحة المشروع ونمو البيانات بما يكفي لاختبار الفلاتر. لا يُبنى بحث معقد لثلاثة مشاريع فقط إن كان سيزيد حجم الموقع أو صيانته بلا فائدة.

| المخرج | القاعدة المعتمدة |
|---|---|
| أرشيف التعريبات | فلترة بالحالة والمنصة والسلسلة فقط. |
| البحث | يبدأ بأيقونة، ويقبل الاسم العربي والإنجليزي والاختصارات وأسماء السلاسل. |
| صفحة السلسلة | تجمع كل الأعمال المرتبطة بالسلسلة، بغض النظر عن كونها فريقًا أو مستقلة. |
| التعريبات المستقلة | صفحة مستقلة مشابهة للأرشيف، تستخرج من `projectType`. |
| الخطط | صفحة مولدة من المشاريع ذات حالة «مخطط»، لا قائمة مكتوبة يدويًا. |
| المدونة | بطاقات مع تاريخ وبحث وتصنيف اختياري وغلاف اختياري وروابط للمشاريع ذات الصلة. |

يُسمح بفهرسة Google للصفحة الرئيسية، والمشاريع الجارية والمكتملة، والمقالات المنشورة، وصفحات السلاسل ذات المحتوى الفعلي. المسودات، صفحات الانضمام، صفحات التجارب، والصفحات الداخلية لا تُفهرس.

### المرحلة E — تجهيز Steins;Gate كمحتوى حقيقي

هذه المرحلة ملك لصاحب المشروع أكثر من كونها عملاً برمجيًا. لا تستبدل النصوص التجريبية بمعلومات غير دقيقة؛ نقص المحتوى أفضل من ادعاء معلومة غير مؤكدة.

| ما يجهزه المالك | الحد المطلوب قبل الإعلان |
|---|---|
| الغلاف | صورة مسموح استخدامها بجودة مناسبة مع نص بديل عربي واضح. |
| الوصف | فقرة قصيرة، ثم وصف موسع بعد مراجعته. |
| المرحلة | المرحلة الحالية من التعريب، من دون نسبة افتراضية. |
| النطاق | ما يشمله إصدار الفصلين 0 و1 وما لا يشمله. |
| الإصدار | رقم النسخة، توافق نسخة اللعبة، نوع الملف، وحجمه إن توفر. |
| التنزيل | مصدر عامل واحد على الأقل، مع مصادر إضافية حين تتوفر. |
| التثبيت | خطوات مدققة تتوافق مع المثبّت أو الباتش الحقيقي. |
| المساعدة | Telegram جاهز، ثم Discord أو البريد عند تجهيزهم. |
| الثقة | تحذير محتوى إن لزم، وبيان أن الباتش ليس نسخة من اللعبة الأصلية. |

### المرحلة F — النشر والتحقق والإطلاق

يبدأ النشر الخاص من بيئة المعاينة فقط، لكن الإعلان العام ينتظر الدومين المخصص وأول إصدار قابل للتحميل. النشر من GitHub إلى Cloudflare Pages يبقى تلقائيًا بعد أن يراجع المالك التغيير؛ لا تحتاج هذه الآلية قاعدة بيانات ولا تؤثر سلبيًا في SEO.

| الخطوة | المسؤول في البداية | شرط الاكتمال |
|---|---|---|
| معاينة محلية | المالك | تشغيل `pnpm dev` والتحقق من الصفحة المعدلة. |
| فحص الإنتاج | المالك أو محرر موثوق لاحقًا | نجاح `pnpm build` وعدم وجود روابط مفقودة. |
| مراجعة المحتوى | المالك | التأكد من التوافق والنطاق وروابط التنزيل. |
| دمج التعديل | المالك | تسجيل تغيير واضح في GitHub. |
| نشر Pages | التكامل الآلي | نشر ناجح للناتج الثابت من الفرع الإنتاجي. |
| فحص ما بعد النشر | المالك | التحقق من الموقع على هاتف ومن بطاقة المشاركة والرابط المباشر. |

## 6. قائمة قبول الإطلاق العام

لا يعلن الموقع العام قبل اجتياز جميع الشروط التالية:

| المجال | شرط القبول |
|---|---|
| البناء | ينجح `pnpm build` وتولد الصفحات HTML المتوقعة. |
| المشروع | صفحة Steins;Gate تعرض الفصلين 0 و1، التوافق، الحالة، والنطاق بوضوح. |
| التنزيل | يوجد رابط عامل واحد على الأقل، وتُظهر النافذة المصادر المتاحة فقط. |
| الهاتف | القائمة وزر التنزيل والنافذة وتعليمات التثبيت قابلة للاستخدام على هاتف. |
| SEO | العنوان والوصف والcanonical وrobots وsitemap وOpen Graph تعمل بالدومين النهائي. |
| الثقة | يوجد بيان الباتش مقابل اللعبة الأصلية، وتحذير محتوى عند الحاجة، وقناة إبلاغ صحيحة. |
| المجتمع | Telegram جاهز برسالة تعريفية أو منشور إطلاق ورابطه صحيح داخل الموقع. |
| السرعة | لا توجد أصول ضخمة محلية أو صور بطيئة بلا داعٍ. |
| الدقة | لا توجد وعود بمواعيد أو نطاقات أو ميزات لم تثبت بعد. |

## 7. سير عمل المحتوى بعد الإطلاق

يبقى المالك محررًا وناشرًا وحيدًا في البداية. عند توسع الفريق، يمكن لعضو موثوق إعداد ملف JSON أو مسودة مقالة من قالب، لكن النشر لا يحدث قبل مراجعة شخص مسؤول. هذا يمنع التعارض في التعديلات ويحافظ على دقة التنزيلات.

1. تُكتب المعلومة أو التحديث في فرع أو مسودة، مع عدم وضع روابط خاصة أو بريد شخصي في المستودع المفتوح.
2. تُعاين محليًا ويُشغَّل البناء للتأكد من الحقول والروابط.
3. يراجع المالك النطاق والتوافق وروابط التنزيل قبل الدمج.
4. ينشر Cloudflare Pages النسخة الثابتة تلقائيًا بعد الدمج.
5. يُفحص الموقع المباشر على الهاتف، وخاصة صفحة المشروع الجديدة أو الإصدار الجديد.

يجوز اعتماد وقت نشر دوري لاحقًا إذا أصبح الفريق يحرر كثيرًا، لكن لا يؤخر إصلاح رابط تنزيل معطل أو مشكلة حرجة؛ هذه تصحح فورًا بعد التحقق.

|---|---|
| تصميم جميل ومعلومات ضعيفة | لا تُنشر صفحة مشروع قبل اكتمال التوافق والنطاق وروابط التنزيل. |
| روابط معطلة | فحص بناء ثم اختبار يدوي من هاتف قبل الإعلان. |
| SEO ضعيف | صفحات مستقلة، مسارات إنجليزية ثابتة، مرادفات أسماء، وقرارات فهرسة صريحة. |
| بطء الموقع | صور ووسائط خارج المستودع، وعدم تحميل مكتبات بحث أو تفاعل قبل الحاجة. |
| وعود يصعب الوفاء بها | حالات ومراحل بدل تواريخ أو نسب مضللة، وسياسة إعلان للمشاريع الواقعية فقط. |
| اختلاف أعضاء الفريق في التحرير | قوالب JSON ومراجعة قبل الدمج، مع محرر مسؤول واضح. |
| خلط ملفات الباتش باللعبة الأصلية | بيان واضح أن الموقع يقدم التعريب، لا نسخة اللعبة، وربط قانوني أو رسمي عند توفره. |

## 9. قائمة الأولويات التنفيذية

| الأولوية | ما ينفذ | سبب الترتيب |
|---|---|---|
| **P0 — قبل أي إطلاق** | إصلاح SEO وOpen Graph و404، ترحيل Steins;Gate، صفحة المشروع، نافذة التنزيل، التوافق، النطاق، التثبيت، الدومين، Telegram. | هذه العناصر تحدد ما إذا كان اللاعب يجد الملف ويستعمله بثقة. |
| **P1 — بعد ثبات أول مشروع** | الأرشيف الجديد، الفلاتر، البحث الثنائي، السلاسل، الخطط، المدونة الواقعية، صفحة الفريق. | تزيد قابلية التصفح دون تأخير أول إصدار. |
| **P2 — بعد وجود استخدام أو فريق** | Discord المنظم، نماذج إبلاغ، تقوية المثبّت، أدوات تدقيق المحتوى، إحصاءات هادفة. | لا تضاف قبل وجود حاجة عملية لها. |
| **P3 — عند وجود سياسة واضحة** | الدعم المالي، تقسيم الدعم، لوحة تحرير، قاعدة بيانات، لغات إضافية. | تتطلب فريقًا أو سياسة أو حجم محتوى لا يوجد بعد. |

## 10. خطوة البدء الموصى بها الآن

الخطوة التالية ليست إضافة صفحة جديدة أو تغيير التصميم. تبدأ الخطة بـ**مرحلة A ثم B على Steins;Gate فقط**: إصلاح بطاقة المشاركة الافتراضية وصفحة 404 وتهيئة SEO، ثم ترحيل ملف Steins;Gate إلى النموذج الجديد دون كسر البناء. بعد ذلك تبنى صفحة مشروعه الجديدة وتختبر على الهاتف. بهذه الطريقة يتحسن أهم مسار حقيقي في الموقع قبل استهلاك الوقت في المدونة أو الدعم أو أدوات لا يحتاجها اللاعب بعد.

> النجاح في Alpha Line لا يعني أن يحتوي الموقع على أكبر عدد من الصفحات؛ بل أن تكون كل صفحة مشروع صادقة، واضحة، سريعة، وسهلة العثور عليها واستخدامها.
