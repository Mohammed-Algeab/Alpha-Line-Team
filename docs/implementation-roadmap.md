# خارطة تنفيذ وإطلاق Alpha Line

> **مرجع القرار:** `docs/accepted-requirements.md` و`docs/questionnaire-responses.md`.
>
> **قاعدة التنفيذ:** لا تُنفَّذ ميزة لأنها «ممكنة» فقط؛ تُنفَّذ عندما تخدم تعريبًا حقيقيًا، أو تحسن قابلية العثور عليه، أو تمنع خطأً في التحميل والمعلومة.

## النتيجة المستهدفة

يصبح الموقع جاهزًا للإطلاق العلني عندما يستطيع اللاعب العثور على صفحة Steins;Gate في Google، فهم حالة التعريب ونطاقه وتوافقه، تنزيل الإصدار المناسب من هاتفه أو حاسوبه، والعودة إلى مصدر موثوق عند حدوث مشكلة. لا يتطلب ذلك قاعدة بيانات أو لوحة إدارة أو دعمًا ماليًا أو إحصاءات زيارة في المرحلة الأولى.

## مسار التنفيذ

| المرحلة | النتيجة العملية | ما يدخل فيها | شرط الانتقال |
|---|---|---|---|
| 0. تثبيت الأساس | موقع ثابت صحيح تقنيًا. | فحص البناء، إصلاح SEO الحالي، 404، روابط وصور المشاركة. | بناء إنتاجي ناجح وروابط أساسية سليمة. |
| 1. ترحيل نموذج المحتوى | ملفات JSON تمثل الحقيقة التحريرية. | حالات ومراحل وإصدارات ومصادر وسلاسل ومقالات. | يستطيع مشروع واحد استخدام النموذج بلا بيانات وهمية. |
| 2. صفحة المشروع | صفحة تنزيل موثوقة للاعب. | رأس المشروع، التوافق، الإصدارات، نافذة تنزيل، نطاق التعريب، المشكلات المعروفة. | تجربة هاتف كاملة على مشروع Steins;Gate. |
| 3. التصفح والاكتشاف | أرشيفات قابلة للعثور والبحث. | فلاتر، بحث ثنائي الاسم، سلاسل، مشاريع مستقلة، خطط ومدونة. | كل صفحة عامة لها رابط ثابت ومسار فهرسة صحيح. |
| 4. المحتوى الحقيقي | أول مشروع جاهز للنشر. | غلاف ووصف ونطاق وتعليمات وروابط تنزيل وإصدار للفصلين 0 و1. | المعلومات وروابط التحميل مدققة. |
| 5. إطلاق محدود ثم علني | نطاق مخصص وموقع متاح. | معاينة نهائية، Cloudflare Pages، Telegram، إعلان الإصدار. | اجتياز قائمة الإطلاق كاملة. |

## المرحلة 0: تثبيت الأساس التقني وSEO

هذه المرحلة تصحح ما يسبق إضافة المزايا. لا نغير الهوية البصرية المعتمدة إلا عند وجود مشكلة وصول أو قراءة أو توافق هاتف.

| المهمة | القرار التنفيذي | أولوية |
|---|---|---|
| إصلاح بطاقة المشاركة الافتراضية | ضمان أن `og:image` يشير إلى صورة حقيقية متاحة لا مسار يعيد 404. | حرجة |
| بطاقات المشاريع | ربط كل صفحة مشروع بصورة مشاركة حقيقية مبنية من غلافها وعلامة Alpha Line. | حرجة |
| صفحة 404 | صفحة ثابتة متسقة مع الهوية، تقود إلى الرئيسية دون طريق مسدود. | عالية |
| الدومين القانوني | استخدام قيمة مؤقتة في إعدادات الموقع ثم توحيد `site` وsitemap وrobots وcanonical بعد شراء النطاق. | عالية عند الشراء |
| فحص الهاتف | تدقيق تحميل الصفحة ورأس المشروع والتنزيل على عرض هاتف فعلي. | عالية |
| سرعة الأصول | إبقاء الصور وملفات الوسائط الكبيرة خارج المستودع واستخدام الروابط العامة المناسبة. | عالية |

## المرحلة 1: ترحيل نموذج المحتوى

تستخدم هذه المرحلة مواصفات `project-content-model-v2.md` و`series-content-model-v1.md` و`blog-content-model-v2.md`. الهدف ليس ملء الموقع بمشاريع تجريبية، بل جعل **إضافة مشروع حقيقي** عملية ذات حقول واضحة.

### 1.1 ملفات المشاريع

يضاف إلى كل مشروع: `status` و`projectType` و`series` و`stages` و`aliases` و`indexing`، مع المحافظة على الحقول الحالية أثناء الانتقال. يبدأ الدعم بهذه الحالات: مخطط، جاري تنفيذ، مكتمل، مؤجل، متوقف، ملغي.

تستخدم مراحل محددة لكل مشروع بدل نسبة تقدم مفترضة. مثال مشروع Steins;Gate: التحضير، استخراج النصوص، الترجمة، الدمج التقني، المراجعة والاختبار، ثم الإصدار. لا تظهر نسبة مئوية إلا إن أدخلها المحرر عن قصد وكان لها معنى حقيقي.

### 1.2 الإصدارات والتنزيلات

يصبح كل إصدار سجلًا مستقلًا يحتوي على رقم الإصدار والتاريخ وتوافق نسخة اللعبة والمنصة ونطاق التعريب وسجل موجز وروابط المصدر. يدعم السجل شارة «إصلاح» ومشكلات معروفة وسحبًا صريحًا للنسخة الضارة.

يبقى لكل إصدار ما يصل إلى ثلاثة روابط مميزة ظاهرة أولًا، بينما تعرض نافذة التنزيل جميع المصادر المتاحة. لا تظهر أزرار لمصادر غير مهيأة.

### 1.3 السلاسل والمقالات

تنشأ ملفات سلسلة مستقلة تربط مشاريع SciADV وغيرها، فلا يصبح تصفح السلسلة تابعًا لتصنيف «فريق» أو «مستقل». وتنتقل المقالات إلى نموذج يدعم الكاتب والتاريخ والتصنيف الاختياري والغلاف والربط بمشروع أو لعبة.

## المرحلة 2: صفحة المشروع، وهي أولوية المنتج

تُراجع هذه الصفحة أولًا قبل توسيع بقية الأرشيفات. لا تزدحم بالمعلومات، بل تقدّم ما يحتاجه اللاعب بالترتيب الذي طلبه المالك.

| الموضع | المحتوى | قاعدة العرض |
|---|---|---|
| رأس الصفحة | غلاف اللعبة، الاسم العربي والأصلي، الحالة، المرحلة الحالية. | لا يظهر زر تنزيل أو آخر تحديث في الرأس. |
| تعريف اللعبة | وصف قصير ثم وصف موسع اختياري. | يقبل غياب قصة التعريب أو سبب الاختيار. |
| حالة التعريب | المراحل ونطاق الإصدار الحالي. | يوضح ما عُرِّب وما لا يزال خارج النطاق. |
| الإصدار والتنزيل | التوافق والتاريخ والملف ونافذة مصادر التنزيل. | التنزيل متاح مباشرة، مع تحذير المشكلات قبل الضغط. |
| التثبيت | تعليمات عملية قابلة للتحديث. | يبدأ النص بسيطًا؛ تضاف الصور أو الفيديو فقط عند الحاجة. |
| الثقة والمساعدة | الإبلاغ الموحد والمساهمون وتحذير المحتوى والمقال/المشروع المرتبط. | لا تعرض تقارير غير متحققة للعامة. |

يُبنى المثبّت الخاص بالفريق كمشروع منفصل لاحقًا. في النسخة الأولى، يكفي أن تشرح صفحة المشروع نوع الملف وكيفية تشغيله بوضوح، ثم يمكن إضافة مزايا المثبّت عند جهوزها.

## المرحلة 3: الأرشيف والبحث والمحتوى التحريري

يبنى أرشيف التعريبات بفلترة الحالة والمنصة والسلسلة فقط. يفتح رمز البحث حقلًا لا يبقى ظاهرًا دائمًا، ويبحث عبر الاسم العربي والاسم الأصلي والاختصارات وأسماء السلسلة. لا يضيف الموقع فلاتر لا يوجد لها محتوى حقيقي.

| المخرج | المصدر | قواعد الفهرسة |
|---|---|---|
| أرشيف التعريبات | جميع المشاريع العامة. | المشاريع الجارية والمكتملة فقط في Google. |
| صفحة الخطط | المشاريع ذات حالة «مخطط». | لا تفهرس قبل وجود محتوى حقيقي أو إعلان واعٍ. |
| التعريبات المستقلة | المشاريع ذات النوع المستقل. | تتبع السياسة العامة للفهرسة بحسب الحالة. |
| صفحة سلسلة | علاقة المشروع بملف السلسلة. | تفهرس إن كان لديها وصف ومشاريع عامة. |
| المدونة | المقالات المنشورة. | كل مقال له تاريخ ورابط ثابت وتظهر تصنيفاته اختياريا. |

تظهر أحدث المقالات في ذيل الصفحة الرئيسية، وتستعمل الأخبار أو التدوينات لإعلان التأجيل أو الإلغاء أو التطورات المهمة بدل تحويل كل تعديل تقني صغير إلى إعلان مستقل.

## المرحلة 4: تجهيز Steins;Gate كمحتوى حقيقي

هذه هي المرحلة التي تمنع الموقع من أن يكون قالبًا بلا قيمة. لا يستبدل أي نص تجريبي بوصف غير مدقق.

| المادة | ما يجب توفيره قبل الإعلان |
|---|---|
| اللعبة | غلاف مناسب، الاسم العربي المعتمد، وصف قصير وموسع، والمنصات المستهدفة. |
| التعريب | المرحلة الحالية، نطاق الفصلين 0 و1، وملخص ما يُترجم أو يؤجل. |
| الإصدار | رقم النسخة، إصدار اللعبة المتوافق، التاريخ، نوع الملف، الحجم عند توفره. |
| التنزيل | رابط واحد عامل على الأقل؛ ثم MediaFire/GitHub/Telegram وفق ما يتوافر. |
| التثبيت | نص قصير مدقق، وتحذير إن كان المثبّت أو النسخة التجريبية يحتاج شرطًا خاصًا. |
| المساعدة | قناة Telegram أو بديل جاهز للإبلاغ، مع بريد رسمي إذا أصبح متاحًا. |
| الثقة | رابط سياسة الاستخدام وبيان أن الباتش ليس اللعبة الأصلية. |

## المرحلة 5: الإطلاق

يكون الإطلاق الخاص ممكنًا على معاينة Cloudflare Pages، لكن الإعلان العام ينتظر النطاق المخصص وأول إصدار قابل للتحميل. يبدأ المجتمع العام بـTelegram؛ تستعد TikTok بقوالب صور وفيديو، ولا تُنشر روابط قناة لم تُجهَّز فعليًا.

### قائمة قبول الإطلاق

| المجال | شرط القبول |
|---|---|
| البناء | `pnpm build` ينجح وتُولد جميع صفحات HTML المتوقعة. |
| الروابط | رابط التنزيل وخطوات التثبيت وروابط التنقل لا تعيد 404. |
| المشروع | صفحة Steins;Gate تذكر نطاق الفصلين 0 و1 وتوافق اللعبة والإصدار بوضوح. |
| الهاتف | زر التنزيل ونافذته وقائمة التنقل قابلون للاستخدام على هاتف. |
| SEO | عنوان ووصف وcanonical وrobots وsitemap وOpen Graph تعمل مع الدومين النهائي. |
| الثقة | تحذير المحتوى عند الحاجة، بيان الباتش واللعبة الأصلية، وقناة إبلاغ جاهزة. |
| المجتمع | Telegram مجهز بمنشور أو رسالة تعريفية ورابطه في الموقع صحيح. |

## ما لا يُنفذ قبل الإطلاق

صفحة الدعم وجمع الأموال، إحصاءات الزيارة، قاعدة البيانات، لوحة التحكم، اللغات الأخرى، التحديثات التلقائية المعقدة، والفيديوهات التسويقية ليست شروطًا للإطلاق. تؤجل حتى تثبت الحاجة إليها بمحتوى أو فريق أو استخدام فعلي.

## تسلسل العمل العملي التالي

1. تنفيذ المرحلة 0: إصلاح Open Graph و404 وتوحيد التهيئة المؤقتة لـSEO.
2. تنفيذ المرحلة 1 على ملف Steins;Gate نفسه، مع الحفاظ على توافق البيانات الحالية.
3. تنفيذ المرحلة 2 وتدقيق صفحة Steins;Gate على الهاتف وسطح المكتب قبل تعميم المكونات على بقية المشاريع.
4. بناء مرحلة الأرشيف والبحث عندما توجد على الأقل بيانات حقيقية كافية للاختبار.
5. تجهيز محتوى الفصلين 0 و1، وروابط التنزيل الحقيقية، وTelegram، والنطاق؛ ثم بدء قائمة قبول الإطلاق.

لا توجد مدة زمنية مفترضة في هذه الخارطة؛ الانتقال بين مراحلها مرتبط باكتمال شروط القبول، لا بموعد تقويمي غير مضمون.
